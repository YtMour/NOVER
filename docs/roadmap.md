## 建议的后续顺序

### P0：让商品可真实售卖

1. 扩展商品资料：亮点列表、授权说明、支持期限和更新说明；基础草稿编辑和发布预览已完成。
2. 引入商品版本 `releases`，明确当前版本、历史版本、变更说明和版本可见范围。
3. 将公开详情改为独立商品详情接口，并补充技术要求和适用场景。效果图上传和展示已提供基础实现。
4. 补齐兑换码、下载票据、撤销和过期的端到端测试，并演练备份恢复。

### P1：降低运营风险

1. 将 `tenant_id` 迁移收口为版本化迁移，增加复合外键、RLS 和对象存储租户命名空间。
2. 增加跨租户负向测试矩阵，覆盖商品、兑换码、资产、权益、票据和活动查询。
3. 将文件存储抽象为本地卷/S3 两种适配，生产使用私有桶和短期签名 URL。
4. 增加上传扫描队列、文件类型白名单、归档包检查和失败重试。
5. 将单一运营账号升级为命名账号、邀请设密、MFA、密码重置和操作审计检索。
6. 增加退款状态同步、售后备注和买家自助查询入口。

### P2：扩大规模和体验

1. 只有在多实例、共享限流或异步扫描需求出现时启用 Redis。
2. 增加公开商品搜索、筛选、版本更新通知和多语言文案结构。
3. 增加基础指标、错误跟踪、告警、清理任务和对象存储生命周期策略。
4. 完成域名、HTTPS、密钥轮换、数据库备份和全新机器部署演练。
