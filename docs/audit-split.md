# 前后台拆分验收记录

日期：2026-11-10

## 摘要

本轮完成用户端与运营控制台的独立化，并补上核心业务数据的第一阶段租户作用域：用户端运行在 `45173`，控制台运行在 `46173/ops-7f3c`，两者分别构建、分别打包、分别部署，并通过显式 CORS 与同一个 Go API 通信。用户端入口不再加载运营登录、后台页面或运营 API 客户端。商品、效果图、交付文件、兑换码、权益、下载票据、下载事件和审计记录现在都带有默认租户字段；运营查询从已验证会话读取租户，不接受前端覆盖。

## 描述

本次调整覆盖四个范围：

1. **前端边界**：`web/` 负责公开商品、兑换、交付和申请；`console/` 负责登录、商品管理、兑换码、成员权限和部署设置。
2. **部署边界**：Docker Compose 增加独立 `console` 服务、端口、Nginx 配置和构建参数。
3. **安全边界**：公开 Origin 与控制台 Origin 使用显式白名单；运营 API 继续使用服务端会话、RBAC 和撤销机制，并对核心业务查询增加租户作用域。
4. **体验边界**：控制台拥有独立顶部壳层、暗色模式、移动端布局和懒加载入口；用户端的 `/ops-7f3c` 不显示后台登录。

## 结论

用户端和运营控制台已经是两个独立的前端应用，不再通过同一个 React 路由壳层提供后台页面。

| 项目 | 验收结果 |

| 用户端 | `http://localhost:45173/`，只包含商品、兑换、交付和加入申请 |

## 后续风险

1. 当前 Compose 仍是单租户自托管，RLS、邀请设密和 MFA 尚未完成；核心业务关系复合外键已完成。
2. 生产环境还需要独立域名、CI 发布/回滚、TLS、访问网关和密钥轮换。
3. 真实出售文件仍应只通过运营端或私有对象存储注入，不进入仓库和镜像。
4. 启动 schema 仍是幂等初始化脚本；生产部署前应拆分版本化迁移并完成跨租户负向测试。
