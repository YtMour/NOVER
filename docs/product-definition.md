# 产品定义

## 1. 产品目标

NOVER 为数字产品提供一个独立的交付空间。成交可以发生在闲鱼、社交平台或其他外部渠道，NOVER 负责把一次外部成交转化为可追踪、可重复下载、可更新的数字权益。

首页面向未登录买家：先介绍 NOVER 的数字产品定位，再展示公开商品目录，并用“完成购买 → 获得兑换码 → 进入交付空间”的三步说明解释交付路径。商品卡统一跳转到兑换入口，避免把实际售卖文件暴露在开源仓库或公开目录中。

### 目标用户

| 角色 | 目标 |
| --- | --- |
| 运营者/卖家 | 创建商品、发布版本、生成兑换凭证、交付文件、处理售后 |
| 买家 | 使用兑换码领取内容、下载指定版本、获取后续更新 |
| 管理员 | 管理账号、审计操作、处理异常和撤销权益 |

### 非目标

MVP 不包含多商户入驻、平台抽成、站内支付、购物车、优惠券、分销、自动读取闲鱼订单和买家社交关系。

## 2. 核心概念

### 商品 Product

面向买家的可交付产品，例如程序源码、网站源码、插件、模板或数字资料。商品本身不等于某个文件；商品可以有多个版本。

### 发布版本 Release

商品在某个时间点的可交付版本，包含变更说明、发布日期、支持状态和一个或多个文件。版本管理属于后续阶段；当前 MVP 把文件直接关联商品。

### 兑换凭证 Redeem Code

一次外部成交对应的领取凭证。兑换成功后，凭证通常进入已兑换状态，并创建购买权益。

### 购买权益 Entitlement

买家获得的访问资格，记录商品、版本范围、有效期、下载次数和更新权限。

### 下载票据 Download Ticket

由 API 短期签发的下载授权，不是永久文件地址。票据过期后必须重新校验权益。

## 3. 业务流程

### 3.1 发布商品

```text
MVP：创建商品 → 上传文件 → 计算 SHA-256 → 买家领取
后续：创建版本 → 上传文件 → 计算 SHA-256 → 安全扫描 → 发布版本
```

MVP 文件写入本机 Docker 私有卷，系统记录对象键、大小、MIME 类型和 SHA-256。生产部署前应替换为有备份和访问策略的私有存储；上传扫描、版本管理和历史版本留存尚未实现。

### 3.2 外部成交后交付

```text
确认外部订单 → 生成/分配兑换凭证 → 发送给买家 → 买家兑换
```

外部订单号用于运营对账和售后，不作为买家访问凭证。订单号、聊天截图和备注不得直接暴露在公开下载页面。

### 3.3 买家兑换

```text
输入兑换码 → 校验格式和状态 → 创建权益 → 展示交付空间
```

兑换接口必须幂等。并发提交同一凭证时只能创建一份有效权益；重复提交会恢复同一交付凭证，不重复创建权益。

### 3.4 下载与更新

```text
打开交付空间 → 选择文件 → 检查权益 → 签发短期 URL → 记录下载事件
```

默认允许买家在有效期内重新下载。下载次数、并发数和更新范围由商品规则决定，而不是硬编码在前端。

## 4. 兑换码规则

- 使用密码学安全随机数生成，目标熵不少于 128 bit。
- 显示格式可采用 `NVR-7KM4-P9QX-2WDF-H8RT`。
- 数据库保存哈希或 HMAC，不保存可直接复制的明文。
- 支持分配、兑换、暂停、撤销、退款和过期状态。
- 页面和日志只显示尾号，例如 `********H8RT`。
- 兑换码、取件 PIN、下载票据分别承担领取、补充验证和短时下载授权职责。

## 5. 商品交付规则

每个商品应配置：

- 权益有效期；
- 最大下载次数或是否不限次数；
- 是否包含后续版本；
- 更新截止日期；
- 使用许可和商用范围；
- 技术支持期限；
- 退款后的权益处理方式。

默认建议：允许短期内重复下载，使用临时下载链接，保留每次下载事件；不要把“下载一次即失效”作为默认策略。

## 6. 状态模型

### 兑换凭证

```text
ASSIGNED → REDEEMED
    │         │
    └──→ SUSPENDED ←──┘
            │     │
       ASSIGNED  REDEEMED

ASSIGNED/REDEEMED/SUSPENDED → EXPIRED or REVOKED
```

### 版本

```text
DRAFT → SCANNING → READY → PUBLISHED → ARCHIVED
                  └──────→ REJECTED
```

### 权益

```text
ACTIVE → EXPIRED
   ├──→ SUSPENDED
   └──→ REVOKED
```

## 7. MVP 验收标准

1. 管理员可以创建商品并上传交付文件。
2. 管理员可以批量签发兑换凭证，并在签发响应中复制明文一次。
3. 买家兑换成功后能看到商品、版本、文件、大小和 SHA-256。
4. 文件从私有本地卷通过 5 分钟短期票据下载；生产存储适配后使用私有对象存储签名 URL。
5. 同一兑换码的并发请求不会创建重复权益。
6. 管理员可以查看最近兑换/下载活动，并暂停、恢复或撤销凭证及其权益。
7. 生产密钥、兑换码明文、订单信息和售卖文件不会进入 Git。

## 8. 当前 MVP 限制

- 文件以本机私有卷保存，适合单实例验证；多副本部署和对象存储尚未实现。
- 文件上传只记录 SHA-256，不执行恶意文件扫描或内容审查。
- 商品没有版本发布和更新渠道模型。
- 下载额度按签发票据计数；同一票据在 5 分钟内可续传或重复请求。
- 管理端使用单一环境变量 Token，不提供管理员用户、TOTP 或 Passkey。
- 退款单据联动、完整审计检索和备份恢复工具尚未实现。
